# Retail Internet-mode gap review

The target is **HOS 19.0.1, Atmosphère 1.12.0, emuMMC**. Its read-only probe found 63 certificate-store entries in 63,532 bytes and successfully read selected entries through the live SSL service. That establishes the store layout and the operating system's read path. The two-account test verified approval, game identity, TLS NEX tickets and room lifecycle for the PICO PARK and Mario Party Superstars profiles. Credentials from the newer native-shaped account adapter also passed both private TLS NEX profiles in a local run, including wrong-token refusal and room cleanup. The retail game's Internet menu has yet to reach the independent realm in a device test. Console probe · Backend test · Native-shaped account receipt

**Trust evidence.** The probe confirms the vendor root entries are present and readable. The original system account client's trust selection is absent from the reviewed public sources, and OpenPak documents additional certificate pinning in some titles. The documented SSL API supports a custom certificate in an application's own SSL context. A successful probe there verifies that application's independent hostname and issuer. Retail-native acceptance still requires a client trust path authorized for the independent service while preserving certificate and hostname checks and the console's original platform trust roots. [libnx SSL API](https://github.com/switchbrew/libnx/blob/master/nx/include/switch/services/ssl.h#L377-L384) · [Switch CertStore reference](https://switchbrew.org/wiki/SSL_services) · [OpenPak client scope](https://github.com/openpak/switch-patcher#what-it-does)

**First link of a local user.** The reference console browser opens `GET /connect/1.0.0/authorize`, which creates the pairing. The other browser signs into its independent account at `/link` and claims the code at `/link/code`. The console then polls `/connect/1.0.0/qr/state` and explicitly approves at `/connect/1.0.0/qr/approve`. The reference `/qr/new` JSON route serves in-app clients such as emulators. HOS exchanges the code at `/connect/1.0.0/api/session_token` and `/api/token` where requested, reads `/2.0.0/users/me`, and completes the persistent user association through BAAS federation and login. Access, ID and refresh tokens have separate purposes. The bridge must retain the same account identity through profile reads, local-user association and refresh. [Console browser handler](https://github.com/openpak/nx-baas/blob/cf93fd71d05296ac321a90fa880af707bf35ed44/internal/nxaccount/na.go#L302-L360) · [Pairing routes](https://github.com/openpak/nx-baas/blob/cf93fd71d05296ac321a90fa880af707bf35ed44/internal/nxaccount/link.go#L373-L440) · [Token handler](https://github.com/openpak/nx-baas/blob/cf93fd71d05296ac321a90fa880af707bf35ed44/internal/nxaccount/na.go#L397-L445)

The current adapter serves `/1.0.0/users`, `/1.0.0/federation`, `/1.0.0/login` and a local grant-backed membership check. Its own browser approval establishes backend identity. Retail profile linking additionally needs the console-facing browser, authorization-code and profile responses above, plus validated device proof if HOS requests `/1.0.0/application/token`. Record exact HOS 19.0.1 calls before adding avatar, profile update, or agreement handlers. The above flow can be implemented narrowly using the published contracts. Importing the full reference would also import features outside this test and its unconditional membership response, which the independent grant-based policy cannot use. **Acceptance order** is boot isolation and native TLS, genuine linkage of one owned account, the installed Mario Party Superstars build reaching its real Internet lobby, then two distinct owned accounts joining the same room and completing a game. Capture status and phase only. The earlier device test can verify native networking and login on one console. The final gameplay result needs a second compatible player.
