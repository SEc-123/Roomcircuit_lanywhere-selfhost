# 0.8.6 审计报告复核

基线提交为 `747369eafdc8907428a222ce2c2c263dc2f47fdb`。审查对象是用户提供的 HTML 完整审计和 Markdown 深度审计，整改继续使用 0.8.6，保留旧验收包用于对照。

## 结论与范围

报告列出的故障路径按实际源码、固定 SDK、复现用例逐项核查。已有运行测试能够验证失败返回、资源释放、协议边界与恢复，但实体 Switch、加载器组合、SD 掉电及双机游戏仍需实测。服务端改动本地验证完成后随源码交付，正式服务器的行为仍取决于后续部署。

HTML B-06/B-07 的 UDP 缺口已整改到进程与描述符归属、别名共享状态、连接对端过滤、Read/Write、地址查询、断开/Shutdown 和关闭清理。虚拟 UDP 的批量消息接口会明确返回不支持。协议支持范围以这些实际实现为准。

Markdown 的“未拦截 Poll/Select”不成立，实际 BSD 服务已经注册这些入口。连接型 UDP、复制描述符和其他等价读写接口另行核查，不能由其中一项存在推导所有 socket 语义完整。

## 兼容性边界

Markdown P2-1 的共享控制缓冲已改为实例缓冲，状态访问受锁保护。runtime A-06 的 NIFM 等待已加入截止时间；12 个同步 IPC worker 在足够多长期阻塞调用下仍可能耗尽，不能保证任意负载下控制请求立即响应。没有证据表明某款普通游戏稳定触发这一条件，因此未在本次未经实机验证的修改中重写 IPC 调度架构。

runtime A-07 的订阅读取和 worker 启动失败已经回传错误。提醒仍依赖 Ultrahand consumer，有限队列不保证跨重启恰好投递一次。主机名称经服务端字符清理后可能与系统名称略有不同。私有 LDN、复杂接入策略和兼容用的 RegisterClient stub 仍按原支持范围处理，不能宣称全游戏或完整 Horizon 服务等价实现。


旧 fork 的流传输协议缺少远端确认和数据序号。单方面添加重传会改变现有对端看到的字节流，无法据此宣称透明、可靠、有序。标准 LAN Play 的 lwIP TCP 和主服务器 TCP 流属于独立实现。

旧联机协议的明文传输是现有兼容边界，更新包仍执行 Ed25519 验签。主机名称用于游戏需要的名称字段，符合本次用户明确选择，应用隐藏昵称不等于网络匿名。

## 验收要求

- 对确认问题保留能失败的基线或实际函数边界测试。
- 完成完整宿主回归、三个 Switch 组件交叉构建及源码指纹核验。
- 核对 SD ZIP、更新包和同版完整源码，提供每项测试范围。
- 发布前仍需用户进行实体 Switch 复测，尤其游戏退出、重复建房、断网恢复和浮层操作。

## 本轮验证结果

- 完整宿主回归：127 组通过；覆盖实际生产函数、真实本机 TCP/UDP、受控 Horizon/文件系统边界。
- 最后一次扫描过滤修正后，生命周期、事件、状态、LCID、密码及 UDP IPC 六项相关回归再次通过。
- App、系统模块及 Tesla 浮层 Switch 交叉构建通过，版本均为 0.8.6；324 个原生源码文件与构建指纹一致。
- 本地隔离服务完成正式签名清单、下载、22 个受管文件安装、恢复确认和设置保留验证。
- 本轮未写入 SD 卡、未部署服务端、未修改线上更新源、未发布或发送渠道消息。
- 同版测试包请手动覆盖安装；0.8.6 不会把另一个同版本清单识别成新版本。
